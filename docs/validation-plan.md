# 자람법 사업성 검증 계획 (2026-08-11 ~ 10주)

> 목적: "부모가 좋아하나"가 아니라 **"이게 사업이 되나"**를 판정한다.
> 판정 기준을 **시작 전에** 못박는다 — 끝나고 정하면 자기합리화가 된다.

---

## 0. 먼저 — 진짜 질문은 무엇인가

"부모에게 필요한가"는 이미 답이 나와 있습니다. 필요합니다. 그건 검증할 필요가 없습니다.
사업성을 죽이는 건 다른 세 가지입니다.

| # | 킬 질문 | 왜 치명적인가 | 어떻게 답을 얻나 |
|---|---|---|---|
| **K1** | **얼마나 자주 쓰나** | 법 질문은 1년에 몇 번이다. 저빈도면 구독이 성립 안 한다 | 4주 재방문·재질문 횟수 |
| **K2** | **누가 돈을 내나** | 부모가 월 5천원을 낼까? 아니면 지자체·어린이집인가 | 지불의사 질문 + B2G 반응 |
| **K3** | **행동이 바뀌나** | "좋네요" 100명보다 **실제로 신청한 5명**이 사업 근거다 | 4주 후 추적 — 신청했나 |

### 북극성 지표 (이거 하나만 봅니다)

> **"자람법 때문에 실제로 신청·제출한 건수"** 그리고 **그 금액 합계**

가입자 수 ❌ · 만족도 ❌ · 체류시간 ❌ — 전부 착시입니다.
"몰라서 못 받을 뻔한 20만 원을 받았다" 사례 **5건**이면 B2C·B2G 양쪽 문이 열립니다.
0건이면 아무리 칭찬받아도 사업이 아닙니다.

### 그리고 미리 알아 둘 것 — 진짜 상품은 '상담'이 아닐 수 있다

법 상담은 저빈도입니다. 하지만 **지원금 신청 기한은 아이가 자라는 내내 계속 발생합니다.**
그래서 팔리는 물건은 "법령 AI"가 아니라 **"놓치지 않게 해주는 알림"**일 가능성이 높습니다.
이번 검증은 그 가설을 확인하는 자리이기도 합니다.

## Phase 0 — 내보내기 전 정비 (3~5일) 🔴 건너뛰면 검증이 무효

지금 상태로 부모를 받으면 **배우질 못합니다.** 아래는 기능 추가가 아니라 계측 장치입니다.

### 0-1. 필수 (없으면 시작 불가)

- [ ] **개인정보처리방침 + 이용약관 페이지**
  실사용자의 이메일·아이 출생 연월·지역을 받습니다. 공모전 시제품일 때와 법적 지위가 다릅니다.
  수집 항목·목적·보유 기간·파기·문의처를 적은 정적 페이지 1장 + 가입 시 동의 체크.
- [ ] **데이터 백업 확인**
  Railway 재배포에 사용자 계정·상담 기록이 날아가면 검증 자체가 증발합니다.
  `JARAMLAW_DATA_DIR`이 영속 볼륨인지 확인하고, **주 1회 수동 백업**이라도 걸어둘 것.
- [ ] **본인이 부모로 완주** — 휴대폰으로, 새 계정으로, 처음부터 끝까지.
  진단 → 결과 → 가입 → 홈 → 물어보기 → 서류. 한 번이라도 끊기면 그게 1순위 수정 대상입니다.

### 0-2. 계측 (없으면 원인을 못 찾음)

- [ ] **퍼널 로그** — 지금 애널리틱스가 **0건**입니다. 어디서 나가는지 모르면 개선을 못 합니다.
  최소 6단계만 세면 됩니다:
  `랜딩 → 진단시작 → 진단완주 → 가입 → 첫질문 → 재방문`
  거창한 도구 필요 없습니다. 이미 있는 audit log에 이벤트 6개만 찍어도 충분합니다.
- [ ] **부모용 피드백 버튼** — 지금은 운영자용 검토 패널만 있고 **부모가 말할 통로가 없습니다.**
  화면 구석에 "이거 이상해요" 한 줄 입력 + 전송. 이게 인터뷰보다 많이 건집니다.

### 0-3. 배송 수단 — 핵심 약속을 시험하려면 필요 (❗️전략 분기)

"먼저 도착한다"를 검증하려면 **도착시켜야** 합니다. 그런데 알림 시스템을 지금 만들면
검증 전에 또 몇 주를 씁니다 — Questy 때와 같은 함정입니다.

**그래서 이번엔 손으로 보냅니다.**

> **컨시어지 알림**: 30~50명이면 사람이 할 수 있습니다.
> 매주 월요일, 대상자를 뽑아 **형님이 직접 카톡/문자로** 보냅니다.
> "○○님, 첫만남이용권 신청 기한이 D-14입니다. 여기서 바로 확인하세요 → [링크]"

이게 자동화보다 나은 이유:
- 알림 인프라 0줄로 **"알림이 행동을 만드나"**라는 질문에 답이 나옵니다
- 반응이 없으면 **알림 시스템을 안 만들어도 됩니다** (몇 주를 법니다)
- 반응이 있으면 그때 만들면 되고, 그땐 만들 이유가 증명돼 있습니다

- [ ] 발송 대상 뽑는 쿼리/화면 (수동이어도 됨)
- [ ] 문구 템플릿 3종 (지원 D-day / 새 지원 매칭 / 놓친 기한 경고)

> 💡 iCal 내보내기 버튼도 없습니다. 만들면 좋지만 **Phase 0 필수는 아닙니다** —
> 캘린더 구독은 부모가 이미 동기부여된 뒤의 기능이라 지금 검증 대상이 아닙니다.

## Phase 0.5 — 어머니가 첫 심사위원 (2일)

채널에 올리기 전에 넘어야 할 진짜 관문입니다.

**어린이집 20년 + 채널 운영자.** 이 도메인에서 형님보다 아는 사람이고, 무엇보다
**채널 신뢰의 주인**입니다. 어머니가 "이건 학부모한테 권하기 좀…"이라고 하면 그 이유가
그대로 시장의 이유입니다.

**하실 것**
1. 아무 설명 없이 휴대폰 건네고 **혼자 써보시게** 합니다 (옆에서 설명 금지)
2. 다 쓰신 뒤 세 가지만 여쭙니다:
   - "학부모한테 권하실 수 있겠어요? 못 하겠으면 뭐 때문에요?"
   - "여기 나온 답, 어머니가 20년 하시면서 아는 거랑 다른 데 있어요?"
   - "이거 채널에 올리면 사람들이 뭐라고 할 것 같아요?"
3. **세 번째 답이 채널 공개 문구가 됩니다.**

> 🔴 여기서 "권하기 어렵다"가 나오면 Phase 2로 가지 말고 그 이유부터 고칩니다.
> 채널 신뢰는 **한 번 쓰면 회복이 느린 자산**입니다.

## Phase 1 — 5명, 옆에서 보기 (1주) · 모집이 아님

숫자를 모으는 단계가 아닙니다. **왜 막히는지**를 보는 단계입니다.

### 대상
어머니를 통해 소개받는 **실제 부모 5명**. 조건은 하나 — 지금 아이를 키우고 있을 것.
(친구·개발자 지인 ❌. 예의로 칭찬하고 끝납니다)

### 진행 (1인당 30분)
1. **아무 설명 없이** 휴대폰을 건넵니다. "한번 써보세요"가 전부입니다
2. **말 걸지 말고 봅니다.** 손가락이 멈추는 곳, 두 번 읽는 문장, 뒤로 가기 누르는 지점을 기록
3. 막혀서 물으면 → "어떻게 하고 싶으셨어요?" 로 되묻고 답은 주지 않습니다
4. 다 쓰신 뒤 질문 (아래)

### 🔴 물어야 할 것 — 과거 행동만

| ✅ 이렇게 | ❌ 이렇게 |
|---|---|
| "최근에 지원금 신청해 보신 적 있어요? 어떻게 알게 되셨어요?" | "이런 서비스 쓰시겠어요?" |
| "놓친 지원 있으세요? 그때 어떻게 아셨어요?" | "유용할 것 같으세요?" |
| "학원이랑 문제 생긴 적 있으세요? 그때 뭘 하셨어요?" | "만족하시나요?" |
| "그때 어디에 물어보셨어요?" | "얼마면 쓰시겠어요?" |

**이유**: 미래 의향은 전부 거짓말입니다(악의 없이). 과거 행동만 사실입니다.
"쓰겠다"는 100명보다 "지난달에 맘카페에 물어봤다"는 1명이 정보량이 많습니다.

### 지불의사는 이렇게 (직접 묻지 않기)
> "지금까지 이런 거 알아보는 데 돈 쓰신 적 있어요? 어디에요?"

돈을 안 써봤다면 그 사람은 **지불 후보가 아닙니다.** 아무리 좋다고 해도요.

### 이 단계 산출물
- 막히는 지점 목록 (우선순위대로)
- "어디에 물어봤나" 답변 5개 → **진짜 경쟁자**가 여기서 드러납니다 (맘카페? 지인? 아무데도?)
- 채널 공개 가능 여부 판단

## Phase 2 — 채널 소프트 오픈 (2주) · 30~50명

### 🔴 전면 홍보 금지

어머니 채널은 **한 번 쓰고 마는 카드가 아니라 반복 자산**입니다. 광고처럼 쓰면 상합니다.

- ✅ 커뮤니티 탭 글 1개 + 영상 말미 자연스러운 언급 1회
- ✅ **어머니 말로** 소개 (형님 말로 하면 광고가 되고, 어머니 말로 하면 추천이 됩니다)
- ❌ 썸네일·제목에 넣기 · 반복 노출 · "출시!" 톤

### 공개 문구 원칙
- **"우수상 받았습니다"를 앞에 두지 마세요.** 부모는 상에 관심 없습니다
- 앞에 둘 것: **"놓치는 지원금 없으신가요"** — 부모가 실제로 걱정하는 것
- 상은 뒤에 한 줄 (신뢰 보강용)
- **베타임을 명시**: "아직 만드는 중이라 이상한 데 있으면 알려주세요" → 기대치를 낮추면 피드백이 늘고 실망이 줍니다

### 이 기간에 하는 일
- [ ] 매주 월요일 **컨시어지 알림** 발송 (Phase 0-3)
- [ ] 퍼널 이탈 지점 매일 확인
- [ ] 피드백 들어오면 **24시간 안에 답장** (30명 규모에선 가능하고, 이게 리텐션을 만듭니다)
- [ ] 치명적 버그만 즉시 수정 — **기능 추가 금지**

### 측정 (주 단위)
| 지표 | 의미 |
|---|---|
| 랜딩 → 진단완주 % | 입구가 막혔나 |
| 진단완주 → 가입 % | 가입이 과한 요구인가 |
| 가입자 중 질문 1회 이상 % | 실사용 전환 |
| **알림 발송 → 클릭 %** | ⭐ K1의 답 — 알림이 행동을 만드나 |
| 2주차 재방문 % | 리텐션 초기 신호 |

## Phase 3 — 4주 추적: 돈이 실제로 움직였나 (4주)

Phase 2 참여자 전원에게 **개별 연락**합니다. 설문 폼 ❌, 카톡 한 줄 ✅.

> "지난번에 써보신 거 있잖아요, 그 뒤로 **실제로 신청하신 거 있으세요?**"

**추적할 것**
- [ ] 신청·제출까지 간 사람 수 (← 북극성)
- [ ] 그 금액 합계
- [ ] "자람법 없었으면 몰랐을 것" 이라고 답한 수 ← **이게 사업 근거의 핵심 문장**
- [ ] 안 한 사람의 이유 (귀찮아서 / 못 믿어서 / 해당 없어서 / 잊어서)

**"안 한 이유"가 제일 중요합니다.** 각각 처방이 다릅니다:
| 이유 | 뜻 | 처방 |
|---|---|---|
| 잊어서 | 알림 문제 | 알림 자동화 (만들 이유 증명됨) |
| 못 믿어서 | 신뢰 문제 | 근거·출처 강화, 전문가 검수 |
| 귀찮아서 | 마찰 문제 | 신청 경로 직결 |
| 해당 없어서 | **매칭 문제** | 🔴 제일 나쁨 — 타깃/데이터 재설계 |

## Phase 4 — 판정 게이트 (10주차) · 기준은 지금 정한다

| 결과 | 조건 | 다음 행동 |
|---|---|---|
| 🟢 **GO (B2C)** | 신청 행동 **5건+** AND 4주차 재방문 **20%+** | 알림 자동화 구축 → 유료 실험 |
| 🟡 **PIVOT (알림 상품)** | 신청 1~4건, 알림 클릭률은 높음 | 상담 축소, **지원금 알리미**로 재포지셔닝 |
| 🟡 **PIVOT (B2G)** | 사례는 나오는데 개인 지불의사 없음 | 지자체 제안 — 사례집이 곧 제안서 |
| 🔴 **STOP (B2C)** | 신청 **0건** | B2C 접기. 공모전 자산으로만 활용하고 다음 것으로 |

> 🔴 **이 표를 지금 확정하고 건드리지 마세요.** Questy 때의 교훈은 "리텐션이 낮았다"가
> 아니라 **"낮다는 걸 늦게 인정했다"**입니다. 기준을 미리 박아두면 그 일이 안 생깁니다.

## 하지 말 것 (실패 패턴)

1. **기능 추가로 반응 없음에 대응하기** — 안 쓰는 이유는 기능 부족이 아닌 경우가 대부분입니다
2. **만족도 조사** — 다들 좋다고 합니다. 아무 정보가 없습니다
3. **가입자 수 자랑** — 100명 가입 0명 사용은 실패입니다. 5명 가입 3명 신청이 성공입니다
4. **채널 전면 홍보** — 자산을 한 번에 태웁니다
5. **개발자·지인에게 검증** — 예의상 칭찬만 돌아옵니다
6. **유료화 서두르기** — 신청 사례 5건 전에는 가격을 논할 근거가 없습니다
